# 索拉尔的主页

`redhand.com.cn` 的源码。静态博客，没有用现成框架——构建脚本在 [`build/`](build/) 下，约几百行 JavaScript。

## 用法

```sh
npm install       # 只有 3 个依赖：markdown-it / highlight.js / js-yaml
npm run dev       # 构建 + 本地预览 http://localhost:4000，监听改动自动重建
npm run build     # 构建到 public/
DEPLOY_REMOTE=user@example.com:/var/www/blog/ npm run deploy
```

写文章：在 `source/_posts/` 下新建 `.md`，front matter 至少要有 `title` 与 `date`：

```yaml
---
title: 文章标题
date: 2025-06-23 21:11:09
tags:
  - cpp
toc: true          # 可省，默认显示目录
---
```

URL 由文件名决定：`source/_posts/memory-order.md` → `/posts/memory-order/`。

### 插图

普通配图直接用 Markdown 图片语法。**示意图用 SVG**，放 `source/diagrams/`，正文里这样引用：

```markdown
:::diagram 07-full-chain
fig. 7 at(int) 的完整调用链
:::
```

第一行是文件名（可省略 `.svg`），第二行是可选图注。SVG 会在构建时**内联进 HTML**——因此它继承页面字体、不额外发请求、文字可选中复制、缩放不模糊。

图自带 `#191919` 底色（比画布 `#0a0a0a` 亮一档），外面套一道 hairline 边框和 8px 圆角，于是它是一个有边界的物件而不是从页面里长出来的一块。底色写在 SVG 内部而非只靠 CSS，这样放大浏览时底色也跟着走。画新图时背景 rect 就用 `#191919`；卡片类元素要比它亮一档（`#212327` + `#363a3f` 描边），否则和底色同色就只剩一圈线了。

`:::diagram` 必须独立成段（前后留空行），否则会被当作上一段的延续文本；这种情况构建会直接失败并提示，不会静默产出坏页面。引用不存在的文件同样会构建失败。

### 站内文章链接

指向本站另一篇文章，用 Hexo 那套 `post_link` 语法：

```markdown
proxy 库的用法见 {% post_link proxy %}
详见 {% post_link kind 在 wsl 下搭建测试集群 %}
```

第一个参数是目标文章的文件名（不含 `.md`），第二个参数是可选的链接文字——省略时自动取目标文章的 `title`，所以改了标题不用回头改引用。

指向不存在的文章会构建失败，并列出全部可用的 slug；写法不合规导致标签没被解析（例如漏了 `%}`）也会失败并显示漏出的原文。两种情况都不会静默把标签原文发到线上。

这套语法只在正文里生效，代码块与行内代码中的同样文本会原样保留。

## 设计

视觉语言是 dark-only 的单一近黑画布（`#0a0a0a`），1px hairline 承担全部层级线索，全站 `font-weight: 400` 不加粗，无阴影，pill 是唯一的交互形状。

排版之外只有一条规则，参照 Karl Gerstner 的程序化设计（*Designing Programmes*, 1964）——不设计版面，而是定一条规则，让版面由内容算出来：

```
一个圆 = 一年，360° = 12 个月
angle = (月 − 1) × 30° + (日 / 30) × 30°
```

每篇文章的发表日期唯一映射到一个角度，画成一根 1px 刻针。这条规则贯穿四个尺度：首页 420px 的太阳（全部文章的真实分布）、索引里 56px 的年环、每行 12px 的条目环、文章页 40px 的定位环。

`#ff7a17` 是全站唯一的点缀色，只标记「当前太阳的位置」——最新一篇文章的角度。每发一篇新文章，太阳就会移动。

修改角度规则只需改 `build/sun.js` 里的 `sunAngle()`，所有尺度会同步跟随。

## 站点标记

侧栏的头盔与 favicon 是同一份图形。原稿是一张 1254×1254 的像素画位图，压缩后有 9780 种颜色、边缘发毛，直接用会在缩放时糊掉，底色也和画布对不上。

所以做成了矢量：探测出真实网格是 48×48（格子边长 26.125px），按格取中位色，再按亮度直方图的峰群量化回 8 色调色板，最后把同色相邻格子合并成矩形——522 个非空格子压到 162 个 `<rect>`，7KB。配 `shape-rendering="crispEdges"` 后任何尺寸都是硬边。

羽饰改用站点点缀色 `#ff7a17`（原稿是红色），与首页那根橙针同色，logo 因此是设计语言的一部分而不是一张外来贴图。

图形内联在 [`build/helm.js`](build/helm.js) 里，不额外发请求；独立源文件在 `build/src/helm.svg`。favicon 是同一份图形加居中留白凑成正方形，PNG 各档直接从网格按整数倍绘制——像素画不能用插值缩放，512px 用 LANCZOS 是 79KB 且边缘发毛，改 NEAREST 只有 2.4KB。只有 16px 那一档装不下 48 格网格，降级用 LANCZOS 保轮廓可辨。

侧栏收起时头盔保留在 48px 窄条上——窄条上没有任何标记就认不出这是哪个站了。

## 篝火

侧栏底部有一团 8bit 篝火——一把剑竖插在火中，黑魂的那种。全站唯一的动画。

**火焰不是手画的。** 手写 ASCII 网格画有机形状很吃力：轮廓总会变成规则的三角斜坡，调了六轮都不像火。最后改为从参考图**降采样**得到基底帧——裁出火焰区、缩到 22 格宽、按亮度与饱和度量化成 5 色、再去噪。不规则的边缘、独立窜起的火舌、散在内部的火心就都保留下来了。剑与柴堆反过来是手画的：剑的护手只有 1 格宽，降采样会把它糊掉。

其余 3 帧由基底帧程序化扰动生成，各对应一种真实火焰的运动：火苗向上窜（边缘向上延伸）、火心上移（中焰提亮成火心）、火焰回落（削掉最外层孤立的火点）。剑与柴堆四帧完全静止，只有火在动。

4 帧精灵图横向拼在一张 SVG 里（88×25 网格，352 个矩形），CSS 只露出一帧宽度、用 `steps` 平移整幅来播放——纯 CSS，无 JS，不额外发请求，帧间没有插值所以边缘始终是硬的。

配色：外焰 `#e35d0a`、中焰 `#ff9a26`、火心 `#ffe08a`；剑与柴 `#5a4632` 暖棕。剑没用头盔那套冷灰——参考图里剑被火映成棕红，用冷灰会显得它跟火不在同一个场景里。

`prefers-reduced-motion: reduce` 下动画停在第一帧，图形仍显示——图形本身是内容，只是不再动。原先那条 reduced-motion 规则只关了 `transition`，`animation` 会漏过去，一并补上了。

没放在首页首屏：那里已经有 420px 的太阳盘作为唯一焦点，再放一团发光的暖色动态物体，两者会互相抢注意力，「一个圆 = 一年」那条规则也就被削弱了。放侧栏底部还有个好处——收起侧栏后它是那条窄带上唯一还在动的东西，正合黑魂里篝火的角色：一个可以停下来歇脚的点。

实现在 [`build/bonfire.js`](build/bonfire.js)。

## 放大浏览

正文里的图片与 SVG 图表都可点击放大：Esc 或点空白关闭，左右箭头在同一篇文章的图之间切换，底栏显示图注与编号。位图放大后按原始像素显示（火焰图原图 2048px，正文里只有 680px），超出视口时可滚动查看。

无 JavaScript 时仍可用：位图外层是指向原图的 `<a>`，脚本只是拦住点击改为开遮罩层；脚本没跑起来时点击照旧新标签页打开原图。放大光标也只在脚本挂载后出现，避免无 JS 时误导。

实现在 [`build/lightbox.js`](build/lightbox.js)，无依赖。

## 代码块

语法高亮走 highlight.js，用它官方的 **github-dark-dimmed** 主题。

字号是 `calc(var(--prose-size) * 0.9)`，跟着正文走而不是写死。写死 14px 时正文抬到 18px，代码就比正文小 4px，断层明显——代码块看着比周围矮一号、行短的块显得空旷（perplexia 那篇的 YAML 块填充率只有 39%）。改成 0.9 倍后中位填充率从 47% 升到 66%，填充不足的块从 59% 降到 30%。取 0.9 而非 1.0 是因为等宽字体在同字号下本就比中文视觉小一档，补偿后仍略小于正文才不抢正文的层级。行内 pill 用同一比例，否则正文变大时它会显得偏小、pill 跟着扁掉。

主题 vendor 到 [`build/vendor/github-dark-dimmed.css`](build/vendor/github-dark-dimmed.css) 而不是构建时从 `node_modules` 读取——升级 highlight.js 时主题不会被意外改掉。相对原版改了四处，都是为了与站点已有规则共存：去掉 `pre code.hljs` 的 padding/overflow（布局归 solaire.css）、去掉 `.hljs` 的 `background: #22272e`（底色用站点的 `#191919`）、三处 `font-weight: bold` 改为提亮（全站 font-weight 恒为 400）、diff 的 addition/deletion 背景色块压成半透明以适应更深的底色。升级主题时重跑这四步，不要手改那个文件。

这里明知有一处冲突而选择了官方原色：关键字色 `#f47067` 偏红，与站点点缀色 `#ff7a17` 在暗底上接近，两者同屏时会有一点互相干扰。换来的是色相分离度——红/紫/蓝/浅蓝/绿五个色相差异明显，扫代码时 token 类别一眼可分；早先那套自定义配色是青/紫/绿，色相挨得太近。而且读者多半在 GitHub 上见过这套色，认知成本更低。

语言标记与复制按钮钉在右上角，不占正文行。这里的布局有个坑：`pre` 自身是横向滚动容器，把标记 `absolute` 到它上面时定位基准是含溢出部分的内容盒，横滚时标记会跟着代码滑走（`cpo` 那篇溢出 206px，标记直接滚出可视区）。`sticky` 也不成——float 到右边缘后没有可粘附的偏移空间。所以脚本会给每个 `pre` 套一层不滚动的 `.codeBlock` 再把标记提上去。

复制按钮由 JS 注入，无 JS 时不存在——渲染一个点了没反应的按钮比没有按钮更糟。`navigator.clipboard` 要求安全上下文，本地 `http://` 预览下会回落到 `execCommand`，两者都失败时按钮会说明「复制失败，请手动选择」而不是假装成功。实现在 [`build/copy-code.js`](build/copy-code.js)。

## 侧栏

左侧导航栏可收起。1180px 及以下默认收起，因为在那个宽度下侧栏（220px）+ 目录轴 + 间距会占掉一半屏宽，正文被挤得放不下一行代码。收起后只留 48px 窄条，正文上限从 1000px 放宽到 1120px（18px 字号下约 62 字/行，略超舒适上限——这是用户主动收起时的取舍，他要的就是更宽）。放宽是必要的：否则大屏上正文已达上限，点收起只会多出空白、正文一动不动，按钮看起来就是坏的。

状态存 localStorage，刷新不丢。初始状态由 `<head>` 里的内联脚本在首帧前决定，避免窄屏先闪一下宽侧栏。这段与放大浏览是全站唯一的两处 JavaScript，都无依赖。

目录轴不可收起 —— 它是当前文章的阅读工具，长文（如 memory-order 有 10 个章节）依赖它。

768px 以下侧栏变成顶部横条，收起按钮隐藏（横条上收起没有意义），CSS 里有一串规则逐条把收起态还原成展开态——收起态的规则是为 48px 竖窄条写的，在横条形态下全都不对。踩过两处漏还原：`.rail` 的横向 padding 被抹成 0，整条横条内容贴死屏幕左边缘（头盔左边一列被切掉、导航第一个圆点半个在屏外）；`.railFoot` 的 `width: 100%` 让篝火漂到横条中间。后者要连着 `html.rail-collapsed` 一起写才能覆盖——media query 不提升特异性，裸 `.railFoot` 的 (0,1,0) 盖不住 (0,2,1)。

## 宽度与自适应

正文栏宽度随视口流动，上限 1000px，字号同步 `clamp(16px, 0.55vw + 12.4px, 18px)`。两者必须一起调：行长的真正约束不是绝对宽度而是每行几个字（中文舒适区间 35–50，上限约 55），而汉字宽等于字号——1000px 在 16px 下是 62 字（超限），18px 下正好 55 字。于是各档宽度下每行都落在 41–56 字之间：768px 是 43 字、1024px 是 41 字、1440px 是 47 字、1782px 及以上是 56 字。

早先用固定的 780px 时，1024px 视口上正文只有 600px（33 字/行，比 768px 手机还窄）——侧栏 220px + 目录轴 200px + 内边距 128px 在 960–1180px 这段吃掉了太多。1180px 断点把目录轴收到 148px、内边距收到 32px，那一档回到 740px。

超宽屏上侧栏与内容区一起居中，不死贴屏幕左边。此前只给内容区设了 `max-width` 却没设 `auto` margin，1920px 视口右侧空掉 708px（37%），2560px 空 53%，3440px 空 65%，而内容全挤在左边。正文占屏比例在 1782px 上从 44% 提到 56%。

图允许比正文更宽：留白够时向两侧各溢出 64px（`--bleed` 取 `min(--s8, --gutter)`，留白不足时自动收成 0，不会顶出页面）。1782px 上正文 1000px、图 1128px。

代码块**不**溢出，与正文同宽。一度也给了它，理由是「代码不该折行，宽一点少滚一次」——但全站 250 个代码块实测只有 4 个真的宽到需要滚，59% 的填充率不到一半、中位数 47%，右侧空出一大片，和正文的对齐关系也断了。加宽 128px 只能让 13 个块（5%）免掉滚动，最宽的那个 1890px 照样要滚；换来的是其余块中位填充率从 66% 掉到 58%。为 5% 牺牲全部不划算。图表不同：它是等比缩放的矢量，宽一点细节确实更清楚。

居中的偏移量集中在 `--gutter` 一个变量里，侧栏的 `left` 与内容区的 padding 都引用它——侧栏是 `position: fixed`，不受父级 padding 影响，两处各写一个固定值必然脱节（中途踩过：实测差 62px）。`--content-max` 由 `--measure-max` 与 `--axis-w` 算出，改正文宽度时它自动跟随；`--measure` 与 `--measure-max` 是同一个值的两种形态（`calc()` 里不能拿 `min()` 求最大宽度），改一个必须改另一个。

### 长 token 的折行

两处会顶出横向滚动的地方，都是「一个 token 比整条正文栏还宽」：

行内代码原本是 `white-space: nowrap`（为保住 pill 形状），但 proxy 那篇满是 C++ 模板名，最长一个 794px，而 768px 下正文栏只有 720px。改成 `overflow-wrap: break-word` 后只在单词自身放不下一整行时才切——那篇 246 枚行内 pill 里只有 11 枚会断，`at()`、`proxy` 这类短的依旧完整。断口不补边框（`box-decoration-break` 默认就是 slice），前段留左圆头、后段留右圆头，读起来是一枚被行尾切开的 pill。

正文链接的文字有时就是裸 URL（android-engine 那篇有一条 391px 的），URL 里的 `/` 与 `.` 不算断点，320px 屏上会顶出 95px。同样用 `break-word`。

这两处都不是改宽度时引入的，而是一直存在、只在特定文章上触发——早先的 12 档测试只采样了一两篇文章，全篇扫过才暴露。

已实测 320–3440px 共 14 档宽度 × 全部 19 篇文章与四类页面 × 展开/收起两态，共 672 组零横向溢出。代码块内部的横向滚动是刻意保留的——代码不该折行，所以检测时会跳过横滚容器内的元素。

## 部署

`npm run deploy` 会构建并同步到 `DEPLOY_REMOTE` 指定的 rsync 目标，例如：

```sh
DEPLOY_REMOTE=user@example.com:/var/www/blog/ npm run deploy
```

需要预先配好对应主机的 SSH 免密。
